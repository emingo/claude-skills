# /followup — capture a ledger entry

Record the note passed as arguments (or, if none, the follow-up just discussed in conversation) in the project's follow-up ledger.

## Hard rules

- **One file per entry.** Entries live in the entry folder (default `docs/fu/`) as `FU-NNN.md` with front matter. Agents find entries by grepping that folder — **never read the generated index** (default `docs/follow-ups.md`); it exists for the user.
- **Never edit the index by hand.** After every entry you create or update, regenerate it from the repo root: `pwsh -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/fu-index.ps1" -Dir <entry folder> -Out <index path>`.
- **Entries are never deleted or renamed;** ids are sequential and stable. Do not commit — the entry rides along with the session's next commit.

## Resolve the ledger

1. Paths the project CLAUDE.md's documentation workflow declares win.
2. Otherwise `docs/fu/` exists → that folder, index `docs/follow-ups.md`.
3. Otherwise `docs/follow-ups.md` exists and does **not** start with `<!-- GENERATED by fu-index` → a **legacy single-file ledger**: say once that `pwsh -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/fu-migrate.ps1"` converts it (one file per entry; the old path becomes the generated index, and its row anchors keep old `follow-ups.md#fu-nnn` links working), then record this entry per `${CLAUDE_SKILL_DIR}/reference/legacy-ledger.md`.
4. Otherwise create `docs/fu/` and write the first entry; the index appears when you regenerate it.

## Steps

1. **Duplicate check — grep, don't read everything:** `grep -il '<keyword>' docs/fu/*.md` for the note's key terms and `grep -l '^files:.*<path>' docs/fu/*.md` for the files involved; open only the hits. If the note re-defers or adds evidence to an **existing** entry, don't create one: append `- **Update (YYYY-MM-DD, <source>):** …` to its body — for a re-deferral write `Revisit when → <new> — <why>` there, set front-matter `revisit:` to `<new>` and `status:` to `open (re-deferred)` — then go to step 4.
2. **Next id:** the highest `FU-NNN` among `docs/fu/FU-*.md` plus one, three digits (`FU-001` in an empty folder).
3. **Write `docs/fu/FU-NNN.md`:**

   ```markdown
   ---
   id: FU-NNN
   title: <short title, one line>
   status: open
   kind: deferred | decision | compromise | limitation
   areas: [<area>, <area>]
   files: [<repo path>, <repo folder>]
   revisit: <milestone id or trigger>
   origin: <branch>, <YYYY-MM-DD> — <what surfaced it>
   ---

   - **What:** <1–3 sentences that stand alone months later, naming the concrete files/types>
   - **Why accepted:** <required for compromise and limitation>
   - **Impacts:** <what else it touches, in prose — docs, contracts, other entries>
   ```

   - Front matter is one `key: value` per line, lists as `[a, b]`, no nesting, so it greps cleanly. Leave a field empty (`files: []`, `revisit:`) rather than inventing a value.
   - **kind:** infer it — "review that later" → `decision`; "accept that cost for now" → `compromise`; "can't do X here" → `limitation`; "do it in M5" → `deferred`. Suffix `(unconfirmed)` when guessed, also on any guessed area.
   - **files:** repo paths or folders the entry is about (a folder covers everything under it). This is how a work package finds its entries from the files it owns — fill it whenever the note names code.
   - **revisit:** required for `deferred`. A bare milestone id (`M5`) blocks that milestone from landing until the entry is resolved or re-deferred.
   - **origin:** when invoked from `/impl-plan`, `/milestone`, `/implement` or `/walkthrough`, name the plan section, milestone, work package or walkthrough point (`— M3 refresh`, `— M4a WP4a.3 (swarm report)`, `— walkthrough 2026-10-01-m2-design #4`).
   - **status:** `open` (optionally `open (re-deferred)`, `open (needs user)`, `open (partially resolved — M4)`) → `done (<sha> or PR #N, YYYY-MM-DD)` / `dropped (<reason>)`. A resolved entry keeps its file and body as history.
   - Link other entries as sibling files (`[FU-012](FU-012.md)`). Other docs link an entry by relative path to its file — from `docs/milestones/`: `../fu/FU-012.md`.
4. **Regenerate the index** (hard rule above).
5. Echo the entry back and ask nothing; if the note was too vague to fill **What** meaningfully, say what's missing instead of inventing details.

## Queries other skills and agents use

```bash
grep -l '^status: open' docs/fu/*.md | xargs grep -lE '^files:.*src/Audio'         # open entries touching a path
grep -l '^status: open' docs/fu/*.md | xargs grep -liE '^areas:.*\baudio\b'        # by area
grep -lE '^revisit: M13\b' docs/fu/*.md                                           # entries that block landing M13
grep -h '^title:' docs/fu/FU-08[0-3].md                                           # titles of known ids
```
